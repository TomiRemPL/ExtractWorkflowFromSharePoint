Manual migracji · stan 17.09.2026

SharePoint Nintex → Oracle APEX

Praktyczny opis przeniesienia logiki workflow do warstwy wywoływanej z systemu zewnętrznego. APEX komunikuje się bezpośrednio z SharePoint, a kontrakt REST może działać synchronicznie lub asynchronicznie.

Najważniejsze ograniczenieEksport potwierdza wyłącznie triggery SharePoint: utworzenie, zmiana i uruchomienie ręczne. Nie zawiera publicznego API Nintex. Docelowy endpoint APEX jest propozycją do wdrożenia i zatwierdzenia.

Zakres

Manual obejmuje wywołanie logiki z systemu zewnętrznego, odczyt i zapis danych SharePoint, mapowanie reguł na APEX oraz kontrakt REST.

Poza zakresem: migracja formularzy Nintex, całej witryny, automatyczny transfer danych i odtwarzanie wszystkich uprawnień użytkowników.

Model docelowy

System zewnętrzny wywołuje endpoint APEX/ORDS. Warstwa APEX waliduje żądanie, odczytuje i aktualizuje SharePoint przez REST oraz zwraca wynik albo identyfikator zadania.

Decyzja blokująca: przed produkcją trzeba potwierdzić uwierzytelnienie z serwera APEX do konkretnej instalacji SharePoint, zwłaszcza przy NTLM/Kerberos.

Reguły bezpieczeństwa

  • Workflow uruchamiaj wyłącznie z whitelisty, nie przyjmuj dowolnego typu akcji od klienta.
  • Trzymaj credentiale w APEX Credential Store, nie w HTML ani kodzie.
  • Waliduj `itemId`, listę, workflowKey i dozwolone pola.
  • Używaj `If-Match`/ETag, aby nie nadpisać równoległych zmian.
  • Loguj correlation ID, wynik, czas, status SharePoint i bezpieczny fragment błędu.
Nie kopiuj sekretów do manuala. Hosty, tokeny, wallet, konta techniczne i ACL są konfiguracją środowiska.
05 · Odbiór

Checklist wdrożenia

otwarte decyzje

Technicznie

  • CSV odczytany jako UTF-16
  • Każdy rekord ma odpowiadający `.nwf`
  • APEX osiąga SharePoint
  • Credential i wallet działają
  • GET, lookup i MERGE przeszły POC
  • Konflikt ETag jest obsłużony

Funkcjonalnie

  • DT01 zapisuje trzy pola wynikowe
  • RKU i Title nie są nadpisywane
  • RT0202 kopiuje właściwy rekord źródłowy
  • RT0701 tworzy poprawny numer ROC
  • Sync zwraca wynik końcowy
  • Async pozwala odpytać status

Decyzje do zatwierdzenia

Przed produkcją należy potwierdzić: sposób uwierzytelnienia, właściciela endpointu, SLA i timeout, autoryzację per workflow, źródło prawdy dla historii, zachowanie przy zmianie elementu w SharePoint oraz czy APEX ma uruchamiać Nintex, czy wykonywać logikę bezpośrednio.
